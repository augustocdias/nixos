# Maintain a verification skill

A feature map rots the moment the app changes. This skill is the upkeep loop for a skill generated by `create-verification-skill`, or any project-local verification skill with a feature map. The unit of rigor is the feature, not every sentence: cover every feature file from source and exercise every feature live.

## Outcomes

Pick one, and say which:

- **clean:** every feature got source and live coverage; nothing needs changing.
- **changed:** proven doc, harness or map corrections were made in the verification skill's directory.
- **blocked:** coverage could not finish or a proven fix could not be made safely. Say exactly what blocked it.

## Edit scope

Edit only the verification skill's own directory: its `SKILL.md`, `features/` and the harness scripts it owns. Product code stays untouched during a run. A behavior the map describes that the app no longer does is either doc drift (fix the map) or a product regression (report it, and keep the map describing the intended behavior).

## Pass

0. **Locate the target.** Find the verification skill under `<git-root>/.dev-skills/skills/` whose body has launch and drive sections and a feature map, usually `verify-<app>/`. With several candidates, ask which one. With none, stop and point at `create-verification-skill`.
1. **Index hygiene.** Read the feature map README and list its sibling files. Fix missing, extra, duplicate or dead entries.
2. **Source wave.** Spawn one read-only, fresh-context subagent per feature file, concurrently, subject to the harness delegation rules. Each explains how the user-facing feature works from source, flags likely doc drift with citations, and returns one concise live-verification recipe. Subagents only read: they drive nothing and edit nothing. Return shape: feature summary, source entry points, likely drift or none, one recipe.
3. **Reconcile.** Every feature file has a returned summary. Merge overlapping recipes into as few app states as practical. Spot-check cited drift; leave clean claims as they are. Sweep recent changes for user-facing surfaces missing from the map, and require a concrete source path before calling one missing.
4. **Live pass.** Required even when source looks clean. The parent owns all driving and follows the verification skill's own launch model: one long-lived instance driven serially for servers and UIs, or a fresh isolated session per drive for short-lived CLIs. Exercise every feature at least once, and hold three invariants the whole pass:
   1. Drive only an instance you have health-checked since it last did something surprising: doctor before the first drive, on each fresh session, and after any failed drive. Where doctor can't see the failure (a wedged UI on a healthy process), reset to a known state or relaunch.
   2. Evidence captured so far survives every cleanup, checked at its named location.
   3. Nothing a drive started outlives that drive's usefulness. Clean failed-iteration residue whether the session is stuck, exited or shared; for a shared instance, clean the residue, not the instance.

   A doctor failure caused by skill drift is drift: fix it under edit scope and retry once, restarting only what the fix invalidated, before calling the pass blocked. A feature that can't be reached is `verified-unreachable` only with the concrete prerequisite (auth, entitlement, OS, external state) and the route attempted; if the map omits that prerequisite, that is drift. Re-drive every harness fix live before keeping it. Final teardown happens after the last drive of the run, and evidence stays.
5. **Triage.** A wrong or missing user-view description is doc drift: fix it. Working behavior the harness can't drive is a harness gap: fix it, with scripts executable and their invocation documented in the skill body. App behavior that is actually broken is a product gap: report it to the user.
6. **Report.** For changed, re-read every changed file and list the corrections with their live proof. For clean or blocked, report the outcome and the coverage honestly.

Keep concise run notes (features covered, unreachable prerequisites, confirmed drift, outcome) under `<absolute-workspace>/debug/<slug>/`.
